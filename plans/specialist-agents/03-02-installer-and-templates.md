# Installer and Templates: Specialist Agents

> **Document**: 03-02-installer-and-templates.md
> **Parent**: [Index](00-index.md)

## Overview

This component owns the project brief format, the deterministic generation of specialist agents,
and their check, removal, and AGENTS.md synchronization. All behavior lives in the existing
generator `scripts/install_agents.py`, preserving its ownership rules: only marker-verified files
are ever replaced or deleted, and hand-authored files are never touched. Generated files are
written with the existing plain-write pattern (no atomic-replace machinery; PF-026).

## Project brief

Path: `codeops/specialists/<role>.md` (project-level in both layouts; AR #12, AR #20). The brief
is the source of truth for the specialist's capability; the generated agent embeds its body.

```markdown
---
schema: 1
role: pg-migration-reviewer
kind: reviewer
description: Reviews PostgreSQL schema and backfill diffs for mixed-version safety. Use for any migration phase.
capability: PostgreSQL migration ordering, backfill batching, and rollback safety
scope: schema changes, backfills, cutover, and compatibility windows
evidence: db/migrations/0042_backfill.sql:1 requires batched backfill; docs/index.md records a manual ordering rule
effort: high
reasoning: max
hidden: false
required-for: any phase changing db/migrations/**
---

## Domain checklist

- Verify every migration is forward-only and idempotent...
```

### Frontmatter rules

Flat `key: value` lines only (no nesting, no multi-line values). Unknown keys are errors.
`role` must equal the filename without `.md`. Values are matched whole-string with
`re.fullmatch` (never `re.match`, which would accept a trailing newline).

| Field | Required | Rules |
| ----- | -------- | ----- |
| `schema` | No | Integer; default `1`; an unknown version is an error (AR #12, PF-029) |
| `role` | Yes | `^[a-z][a-z0-9-]{1,40}$` via fullmatch; not a catalog role; not an OpenCode built-in (`plan`, `build`, `general`, `explore`, `scout`, `compaction`, `title`, `summary`); not a DOS device name (`con`, `nul`, `aux`, `prn`, `com1`–`lpt9`); no trailing dot or space (AR #15, PF-009, PF-025) |
| `kind` | Yes | `reviewer` or `executor` (AR #9) |
| `description` | Yes | Single line; sanitized; ≤200 characters (AR #12) |
| `capability` | No | Single line; sanitized; ≤200 characters |
| `scope` | No | Single line; sanitized; ≤200 characters |
| `evidence` | No | Single line; sanitized; ≤500 characters |
| `effort` | No | `low`, `medium`, `high`; maps to temperature via the existing table (`scripts/install_agents.py:58-62`) |
| `reasoning` | No | `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` (AR #19) |
| `hidden` | No | `true` or `false`; default `false` (AR #7) |
| `required-for` | No | Single line; sanitized; ≤200 characters; shown in the AGENTS.md index |

Body: Markdown, at most 16384 bytes (exactly 16 KB). Control characters are stripped; Markdown
structure (newlines and spacing) is preserved. The body is never whitespace-collapsed and never
byte-verbatim re-emitted without the control-character pass (PF-027).

Sanitization applies to every value that can reach a prompt or AGENTS.md, and runs to a
**fixed point**: strip control characters; then repeat the whitespace-collapse and `<!--`/`-->`
removal pass until the value stops changing (removal can stitch a new marker and can leave double
spaces, so the whole pass repeats); reject if any marker sequence remains; finally trim and
length-cap. This makes marker injection impossible (PF-007, PF-027).

## Generated agent

`scripts/install_agents.py --custom <role>` writes `.opencode/agents/<role>.md` with the existing
plain write. All interpolated frontmatter strings are emitted as double-quoted, backslash-escaped
YAML scalars (JSON-style via `json.dumps`), so YAML indicator characters in a description cannot
break parsing (PF-008).

```markdown
# Generated by CodeOps install_agents.py
# Role: pg-migration-reviewer | Template: domain-specialist-reviewer
# Do not edit this file manually — regenerate with: install_agents.py
---
description: "Reviews PostgreSQL schema and backfill diffs for mixed-version safety. Use for any migration phase."
mode: subagent
temperature: 0.1
hidden: false
reasoningEffort: max
permission:
  read: allow
  grep: allow
  glob: allow
  edit: deny
  bash: allow
---

<domain-specialist-reviewer contract>

---

<brief body>
```

Rules:

- Template is selected by `kind` (AR #9).
- `hidden` comes from the brief; default `false`.
- `reasoningEffort` resolution order: `routing.roles.<role>.reasoning` → brief `reasoning` →
  `max` (AR #10, AR #19).
- `effort` resolution order: `routing.roles.<role>.effort` → brief `effort` → `high`.
- `model` is emitted only when `routing.roles.<role>.model` pins one; no hardcoded model.
- Permissions: reviewer `edit: deny` **always**, even when a `workspace-write` sandbox override is
  present; executor `edit: allow` by default, and a sandbox override may only tighten it
  (`read-only` denies edit and bash — the existing mapping wins over the template default).
  `bash` stays `allow` for reviewer inspection unless the sandbox mapping denies it
  (`scripts/install_agents.py:64-69`; PF-010, PF-011).
- A target that exists without the CodeOps marker (hand-authored) is refused with guidance; never
  overwritten. Default catalog roles keep their existing behavior.

## CLI surface

| Flag | Behavior |
| ---- | -------- |
| `--custom <role>` | Validate brief, generate agent (AR #13). Singular role only; comma lists are invalid (PF-020) |
| `--remove-custom <role>` | Report; delete only with `--yes` (AR #11) |
| `--sync-agents-md` | Render/update/remove the AGENTS.md managed block (AR #14) |
| `--check` | Existing default-role checks plus brief/agent/AGENTS.md states (AR #13) |
| `--dry-run` | Print intended changes for every mode; write nothing. **Dry-run always wins over `--yes`** (PF-014) |
| `--yes` | Confirm destructive `--remove-custom` deletions |
| Existing `--project`, `--roles` | Unchanged behavior |

`--custom` and `--sync-agents-md` are separate operations so failures are attributable;
`setup-routing` writes routing policy first, then runs `--custom`, then `--sync-agents-md`, then
`--check` (PF-019). `--remove-custom --yes` also runs the sync so the index never lists a removed
role; the sync runs before the files are deleted so a malformed or unwritable AGENTS.md fails
without leaving a stale index (PF-022).

## AGENTS.md managed block

Markers: `<!-- CODEOPS-SPECIALISTS:START -->` and `<!-- CODEOPS-SPECIALISTS:END -->` (AR #14).

```markdown
<!-- CODEOPS-SPECIALISTS:START -->
Specialist agents (routing: `codeops/codeops.json`; briefs: `codeops/specialists/`):
- `pg-migration-reviewer` — "Reviews PostgreSQL schema and backfill diffs for mixed-version safety. Use for any migration phase." (Required for: any phase changing db/migrations/**)
<!-- CODEOPS-SPECIALISTS:END -->
```

- Three fixed lines (START, intro, END) plus one line per specialist. The block is a soft budget:
  projects are expected to stay at or under fifteen entries / about forty lines; beyond that the
  block ends with `- …and N more; see codeops/specialists/` instead of growing without bound.
  `--check` reports the entry count (PF-029).
- **File absent or empty:** create AGENTS.md containing only the managed block (PF-004).
- **Missing trailing newline:** append a newline, then one blank line, then the block.
- **CRLF file:** write the appended/replaced block using the file's dominant line ending; marker
  detection tolerates CRLF.
- **Neither marker present and briefs exist:** append the block at the end, separated by one blank
  line.
- **Both markers present:** replace only the content between them; surrounding bytes are unchanged.
- **Exactly one marker, duplicate START/END pairs, or END before START:** error; file is left
  unchanged.
- **No briefs and markers present:** remove the block and one adjacent blank line.
- Re-running with unchanged briefs leaves the file byte-identical (idempotent).
- Description and `required-for` are sanitized to a fixed point before insertion; marker sequences
  cannot be injected.
- `setup-routing` is the only skill that invokes this mode; `analyze-project` preserves the block
  when it rewrites its own managed section.

## `--check` semantics

For each `codeops/specialists/*.md`:

| State | Condition | Output |
| ----- | --------- | ------ |
| Invalid brief | Frontmatter missing/invalid/reserved name/oversize | `INVALID: <role> — <reason>` (PF-021) |
| Missing | No generated agent at `.opencode/agents/<role>.md` | `MISSING: <role>` |
| Stale | Re-rendered content differs from the file on disk | `STALE: <role>` |
| Index state | AGENTS.md absent, block missing, or block differs | `AGENTS.md MISSING (file)`, `AGENTS.md MISSING (block)`, `AGENTS.md STALE` |
| Orphan | Marker-generated `domain-specialist-*` agent has no brief | `ORPHAN: <role>` |
| Collision | Target path exists without the CodeOps marker | `HAND-AUTHORED: <role> (not managed)` |

Custom states use the `ROLE: <role>` token form above; default-role checks keep their current
output. Exit code 1 when any issue is reported; 0 with `OK: N default, M custom` when clean.

## Removal

`--remove-custom <role> [--yes]`:

1. Apply the create-path validation (slug, reserved/built-in names, catalog collisions) and refuse
   any catalog or built-in role even when a generated file exists (PF-005).
2. Resolve the generated agent; refuse unless it carries the CodeOps marker **and** the matching
   `Template: domain-specialist-*` comment.
3. Resolve the brief. If the generated agent is missing, report `MISSING` and delete only the
   brief with `--yes` (restoration semantics). If the brief is missing, report the inconsistency
   and continue with the agent file for orphan cleanup.
4. Render and validate the post-removal AGENTS.md block first; abort on malformed markers or an
   unwritable file before deleting anything (PF-022).
5. Without `--yes`: print the exact files that would be deleted; exit 0. `--dry-run` behaves the
   same even when `--yes` is present (PF-014).
6. With `--yes`: delete the agent and brief, then write the updated AGENTS.md block.
7. If the target path is a symlink, unlink the link itself and never follow it; on any other
   write failure the link is left untouched (PF-006).
8. Never delete catalog agents, `agents/` sources, or hand-authored files.

`setup-routing` removes the role from `codeops.json` routing policy after the installer succeeds
and warns when an active plan references the removed role; `exec-plan` then falls back to a dynamic
packet and reports it (AR #16).

## Error handling

| Error case | Handling | AR Ref |
| ---------- | -------- | ------ |
| Brief missing for `--custom` | Error naming the expected path; exit 1; no write | AR #18 |
| Malformed frontmatter, unknown key, missing required field | Error naming the field and line; no write | AR #12, #18 |
| `role` does not match filename | Error; no write | AR #12 |
| Invalid, reserved, or built-in role name | Error naming the rule; no write | AR #15, PF-009 |
| Body over 16384 bytes | Error with the limit and measured size; no write | AR #12, PF-028 |
| Hand-authored target exists | Refuse; instruct to rename or remove manually | AR #15 |
| Symlinked target directory, agent file, or AGENTS.md | Refuse; never write through a link | PF-006 |
| AGENTS.md absent | Create it containing only the managed block | PF-004 |
| AGENTS.md malformed/duplicate/reversed markers | Error; file unchanged | AR #14, PF-004 |
| AGENTS.md unwritable | Error before any deletion; generated agent remains | AR #18, PF-022 |
| `--remove-custom` target not marker-owned or catalog/built-in | Refuse; no deletion | AR #11, PF-005 |
| Invalid brief during `--check`/`--sync-agents-md` | Report `INVALID: <role>`; exit 1; sync refuses to process it | PF-021 |
| Removal while a plan references the role | Installer does not block; `setup-routing` warns; `exec-plan` falls back | AR #16, #18 |
| Provider rejects `reasoningEffort` | Documented override via `routing.roles.<role>.reasoning`; no auto-detection | AR #19, PF-031 |

## Security

- Role-name allowlist via fullmatch, reserved/built-in/DOS/trailing-dot rejection precede any path
  use (AR #15, PF-009, PF-025).
- Brief path resolution canonicalizes and stays inside `<project>/codeops/specialists/`; symlink
  escapes are rejected, and symlinked target directories, agent files, and AGENTS.md are refused
  with the same lstat pattern the Node installer uses (`bin/install-agents.mjs:388-394`; PF-006).
- Prompt-bound text is sanitized to a marker-free fixed point, length-capped, and written as
  escaped YAML scalars before entering agent frontmatter or AGENTS.md (PF-007, PF-008).
- Reviewer specialists are read-only regardless of routing policy; executor write access is the
  default and can only be tightened (PF-010, PF-011).
- The installer never reads credentials, environment secrets, or files outside the project root
  and the plugin package.

## Testing requirements

- Behavioral spec tests in `scripts/install_agents.spec.test.mjs` spawn `python3` (with
  `CODEOPS_PLUGIN_ROOT` overridden to the checkout root) and cover ST-1 … ST-29 and
  ST-36 … ST-42; the content (ST-30 … ST-32) and migration (ST-33) cases live in their own files
  (AR #17, PF-030).
- Implementation tests in `scripts/install_agents.impl.test.mjs` cover sanitization boundaries,
  parser edge cases, quoting, and idempotent writes.
- The flat-layout migration regression (ST-33) runs `scripts/codeops-migrate.sh --dry-run` **and
  an apply-mode preservation fixture** on a repo containing `codeops/specialists/` and
  `codeops/codeops.json` (PF-013).
